# 系统架构与 AI 实现

## 一、总体架构

```
                        ┌──────────────────────────────────────────┐
   浏览器  ────────────▶│  Vue3 SPA（static/app，hash 路由）        │
   /app/                │  助手 · 看板 · 预警 · 画像 · 取数 · 知识库 │
                        └───────────────┬──────────────────────────┘
                                        │ REST + SSE
                        ┌───────────────▼──────────────────────────┐
                        │  Spring Boot 2.7（单 jar）                │
                        │  ai/web  AiController                     │
                        │  ai/service  对话编排 / 主动洞察 / NL2SQL  │
                        │  ai/agent    Agent 循环（最多 5 轮工具）   │
                        │  ai/tool     9 个业务数据工具 + 注册中心   │
                        │  ai/llm      远程客户端 / 本地规则 / 路由  │
                        │  ai/rag      知识库服务 + 混合检索         │
                        │  ai/data     只读 SQL 执行器（安全护栏）   │
                        │  ai/store    会话存储 + 幂等建表           │
                        ├──────────────────────────────────────────┤
                        │  原有学籍业务：Controller/Service/Mapper   │
                        └───────────────┬──────────────────────────┘
                                        │ JDBC / MyBatis
                        ┌───────────────▼──────────────────────────┐
                        │  PostgreSQL student_manage                │
                        │  业务表（原有） + ai_* 表（新增，幂等创建）│
                        └──────────────────────────────────────────┘
```

**设计原则：AI 层只读业务表，业务层完全不知道 AI 层存在。** 这样升级随时可回退，评委也能清晰区分"原有系统"与"AI 增量"。

## 二、双引擎（可插拔大模型）

### 2.1 接口抽象

```java
public interface LlmClient {
    String provider();                                  // 展示名
    boolean available();                                // 是否可用
    ChatResult chat(List<LlmMessage> messages,
                    List<ToolSpec> tools,
                    StreamHandler handler);             // 支持流式 + 工具调用
    boolean supportsEmbedding();
    float[] embed(String text);
}
```

| 实现 | 说明 |
| --- | --- |
| `OpenAiCompatibleClient` | `/chat/completions`（SSE 解析 tool_calls 增量拼接）与 `/embeddings`，仅依赖 HttpURLConnection + Jackson，零额外依赖。适配 DeepSeek / 通义 / 智谱 / OpenAI / vLLM / Ollama(v1) |
| `HeuristicClient` | 本地规则引擎：意图识别 → 工具计划 → 并发执行 → 模板渲染 → 逐字流式输出 |
| `LlmClientRouter` | `@Primary`。按 `ai.mode`（auto/remote/local）选择；远程连续失败 3 次触发熔断，自动降级本地并记录 `lastError`，可 `POST /ai/breaker/reset` 手动重试 |

### 2.2 本地规则引擎如何做到"功能不缺项"

`HeuristicClient` 不是简单的 if-else 兜底，而是一个小型规划器：

1. **意图识别**：正则 + 关键词打分，识别"学生画像 / 名单查询 / 成绩分析 / 学籍总览 / 风险预警 / 奖惩 / 异动 / 制度问答 / 取数"等意图；
2. **参数抽取**：从问句里抽姓名、班级、专业、院系、性别、风险等级、维度（班级/课程/院系）；
3. **多工具计划**：一个问句可触发多个工具（例如"哪些学生需要重点关注" → `risk_warning`；"学校整体情况" → `stats_overview` + `analyze_scores`）；
4. **模板渲染**：按工具结果类型生成 Markdown（指标用无序列表、明细用表格、画像用分节小标题），并追加"数据质量提醒"与后续建议；
5. **流式**：按标点切块逐字推送，前端体验与真实模型一致。

> 效果：在完全离线、无任何密钥的环境下，6 个页面、9 个工具、SSE 全过程可视化全部可用。

## 三、Agent 工具循环

`AgentEngine.execute()` 的核心循环（最多 `ai.max-tool-rounds`=5 轮）：

```
messages ← [system(含库表结构+数据口径+红线)] + 历史(最近3轮) + 用户问题
loop:
    result ← llm.chat(messages, tools)
    if result 有 tool_calls:
        并发执行工具（每个工具独立计时）
        → 推送 step 事件（running → success/failed，含 data/chart）
        → 把工具结果压缩为文本追加为 tool 消息
        continue
    else:
        逐字推送 delta 事件 → 结束
```

要点：

- **工具结果压缩**：`ToolResult.toModelText()` 把结构化数据截断到 4000 字符再喂给模型，避免上下文爆炸；而完整数据只走 SSE 给前端渲染，做到"模型看摘要，用户看全量"。
- **两个出口**：`/ai/chat/stream`（SSE，前端用）与 `/ai/chat`（同步 JSON，接口验收用）。
- **场景化提示词**：请求带 `scene`（assistant/dashboard/warning/knowledge/sql），`Prompts.sceneHint()` 动态追加场景要求。

## 四、RAG 制度知识库

### 4.1 数据模型

| 表 | 用途 |
| --- | --- |
| `ai_knowledge` | 文档：标题、分类、标签、来源、正文、片段数 |
| `ai_knowledge_chunk` | 片段：文档 ID、序号、内容、embedding（JSON 文本，可空） |

启动时 `SchemaInitializer` 用 `CREATE TABLE IF NOT EXISTS` 幂等建表；`ai_knowledge` 为空时自动导入 `classpath:ai/knowledge-seed.json`（9 篇示例制度：学籍管理、转专业、休复学、考试纪律、学业预警、奖助学金、成绩管理、毕业审核、数据安全）。

### 4.2 切分与检索

- **切分**：按空行优先，超长段落按句号/分号二次切分，片段带标题前缀（提升召回时的语义完整度）。
- **关键词检索**：中文二元切分（无需外部分词器）+ TF-IDF 式打分：
  `score = Σ (1 + log(tf)) × log(1 + N / (1 + df))`，并叠加标题/分类命中加权。
- **向量检索（可选）**：配置 `ai.embedding-model` 后，`/embeddings` 生成向量并与关键词得分归一化融合。
- **回退**：任何向量调用失败都不影响关键词检索，`embeddingEnabled=false` 时界面上会明确标注"关键词检索"。

### 4.3 可溯源

检索结果以 `citations` 事件推给前端，回答下方展示"制度依据"卡片（文档名 + 相关度 + 片段原文）；同时写入 `ai_message.citations`，历史会话重新打开仍可复核。

## 五、NL2SQL 与安全护栏

`SqlAssistantService.ask()` 流程：

```
自然语言 → (远程) 让模型输出 {"sql","explanation"}  → 本地模板兜底（7 类常用取数）
        → ReadOnlySqlExecutor.validate()  ← 6 道闸门
        → 外层包裹 LIMIT 200+1 执行（只读事务 + 8s 超时）
        → 返回 {sql, explanation, columns, rows, total, truncated, elapsedMs}
```

`ReadOnlySqlExecutor` 的 6 道闸门：

1. **必须 SELECT/WITH 开头**；
2. **单条语句**（去除注释后不允许出现分号）；
3. **关键字黑名单**：insert/update/delete/drop/alter/create/grant/copy/pg_sleep/pg_read_file/information_schema/for update 等 40+ 词；
4. **表名白名单**：仅允许 12 张业务表/视图，正则提取 `FROM|JOIN` 后的表名逐一校验；
5. **必须引用白名单表**（防止 `SELECT 1` 之类的探测）；
6. **执行层加固**：`SELECT * FROM ( 用户SQL ) __ai_result LIMIT 201`、`PreparedStatement.setQueryTimeout(8)`、只读事务。

> 前端 `#/sql` 页面把生成的 SQL 全文高亮展示，并列出以上护栏，让"AI 直接写库"这件事变得可审计。

## 六、降级与容错矩阵

| 故障 | 表现 | 系统行为 |
| --- | --- | --- |
| 未配置 API Key | `/ai/status.mode = local` | 本地规则引擎接管，回答前缀标注"本地推理模式" |
| 远程模型超时/报错 | 连续 3 次失败 | 熔断降级本地，`lastError` 返回给前端展示 |
| 向量模型不可用 | `embeddingEnabled=false` | 自动退化为关键词检索 |
| 工具执行异常 | 该步骤 `status=failed` + error | Agent 把错误信息交给模型，由其给出替代方案 |
| 查询无结果 | `rows=[]` | 工具返回 hints（放宽条件建议），模型据此回复 |
| SQL 未通过校验 | `success=false` + message | 前端展示待审 SQL 与拒绝原因，不执行 |
| 数据库缺数据 | 成绩覆盖率 40% 等 | AI 主动指出数据缺口，并说明对结论的影响 |
