# 演示脚本

> 全程约 6 分钟。默认**不配置大模型密钥**（本地规则引擎），先证明"系统始终可用"；再补一句"配置密钥后即由大模型接管，能力只增不减"。
> 若现场要展示大模型能力，请在演示前执行：`$env:AI_API_KEY="sk-xxx"` 后重启。

---

## 0. 开场（20 秒）

打开 <http://localhost:8080/app/>

> "这是一套真实的高校学籍管理系统，后端 Spring Boot + PostgreSQL，原有功能都在。我们没有推倒重来，而是在它之上做了一层 AI 原生改造——**不改业务代码，只加 AI 模块**。左边六个页面就是这次新增的能力。"

---

## 1. AI 助手：让 AI 自己去取数（90 秒）

进入 **AI 助手**，点击引导卡片「学生全景画像」，或直接输入：

```
查一下张三的情况
```

**看点（边讲边指屏幕）：**
1. 左侧时间轴出现「学生全景画像 / 已完成 / 7ms」——**这是 AI 自己决定调用 `get_student_profile` 工具的证据**，不是写死的模板；
2. 结果卡片展示学籍、平均分、成绩明细、学籍异动；
3. 回答是逐字流式出现的，末尾带"本地推理"标签。

> "注意这里的信息全部来自数据库，模型只负责组织语言。AI 没有任何机会编造学生数据。"

接着输入第二个问题（体现多工具/多维度）：

```
各班平均分对比
```

> "它会自己选 `analyze_scores` 工具，并把结果直接渲染成图表。"

---

## 2. 智能看板：AI 主动发现问题（60 秒）

切到 **智能看板**。

> "传统系统要人去看报表才可能发现问题，这里是 AI **主动**跑完分析后给出的洞察。"

逐条念洞察卡片（真实产出，随数据变化）：

1. **成绩数据覆盖**：4/10 名学生存在成绩记录，覆盖率 40% —— 提示画像与预警结论需谨慎使用；
2. **学业风险分布**：中风险 6 人；
3. **学籍异动积压**：1 条待审核；
4. **成绩数据质量**：检测到 3 条超过 100 分的成绩记录，属录入异常。

> "最后一条很关键：系统里确实有 149、190 分这样的成绩。AI 不是照着模板夸奖数据，而是**主动指出数据本身有问题**，并说明会影响平均分与排名。这才是'懂业务'。"

底部「数据质量体检」三张卡再次强化这一结论。

---

## 3. 学业预警：规则筛得准 + 大模型说得好（70 秒）

切到 **学业预警**。

> "预警的关键是**筛得准**。所以这里用规则引擎：不及格门数、平均分、待审异动、成绩缺失、异常分数，规则是确定的、可审计的。"

- 点上方「高风险 / 中风险 / 低风险」筛选，名单与指标实时变化；
- 右侧「AI 分层干预建议」给出分层处置（高风险 3 个工作日内约谈、中风险 2 周内跟踪、缺成绩先核实数据）；
- 表格每行有「画像 / 追问」按钮 —— 点「追问」会带着这位学生的问题直接跳进 AI 助手继续聊。

> "规则负责筛，大模型负责说。两者结果同屏对照，方便老师判断。"

---

## 4. 学生画像：一人一档 + AI 点评（50 秒）

切到 **学生画像**，点击任意学生（例如 `2023002 李四`）。

> "左侧是名录，右侧是 360° 画像：学籍 + 成绩 + 奖惩 + 学籍异动 + 档案材料，数据来自 `get_student_profile` 工具。"

向下滚动看「AI 画像点评」与建议清单。

> "点评里所有数字都能在下面的'全景档案'里找到出处。数据缺失时它会明说——比如'档案材料为空，建议核实是否已上传'，而不是假装知道。"

---

## 5. 智能取数：不会写 SQL 也能取数（70 秒）

切到 **智能取数**，输入或点选示例：

```
各班平均分和及格率
```

**看点：**
1. 生成的 **SQL 全文高亮展示**（带 `COALESCE(d.dept_name,'未分配')` 这种真实口径）；
2. 「统计口径」标签说明含义；
3. 结果表格 + 自动图表；
4. 右侧「安全护栏」5 条说明。

> "AI 直接写库风险很高，所以我们做了 6 道闸门：只允许单条 SELECT、40 多个关键字黑名单、12 张表白名单、外层强制 LIMIT 200、只读事务、8 秒超时。**生成的 SQL 全部展示给用户，统计口径可复核。**"

可再问一句自由表达的（例如"男女比例是多少"）展示模板兜底能力。

---

## 6. 制度知识库：RAG，让回答有出处（50 秒）

切到 **制度知识库**，检索框输入：

```
转专业需要什么条件
```

**看点：**
1. 命中 4 个片段，按相关度排序，第 1 条相关度 1.0；
2. 片段直接展示原文；
3. 点「基于该制度追问」跳到助手，AI 会带着引用作答，回答下方有「制度依据」卡片。

> "制度类问题最怕模型编条款。我们把制度原文入库、切分、检索，回答必须标注出处；知识库没有的条目，它会说'暂无该规定'，而不是虚构。"

还可以点「新建」当场粘贴一段制度、保存、立即检索到 —— 证明知识库是活的，不是写死的提示词。

---

## 7. 收尾（20 秒）

> "总结一下：**取数**用自然语言、**制度**可溯源、**风险**主动发现、**画像**一人一档；所有结论来自真实数据，所有推理过程在界面可见；而且——现在这台机器**没有配任何大模型密钥**，整套系统依然完整可用。
>
> 我们做的不是给系统贴一个聊天框，而是把 AI 变成学籍业务的一部分。"

## 附录 A：异常与兜底话术

| 常见情况 | 应答话术 |
| --- | --- |
| 被问"没配 Key 也能用？" | "是的。远程模型与本地规则引擎实现同一个接口，路由器自动切换；连续失败 3 次还会熔断降级。等于给 AI 装了双回路供电。" |
| 网络/模型挂了 | "现在展示的就是降级路径：`/ai/status` 显示 `mode=local`，回答前缀会标注本地推理模式。业务不中断。" |
| 被问"AI 会不会乱改数据？" | "不会。AI 层只有查询工具，唯一的动态 SQL 通道是只读执行器：白名单 + 黑名单 + 只读事务 + LIMIT + 超时，且 SQL 全文展示。写操作仍然走原来的业务接口。" |
| 被问"和直接调 GPT 有什么区别？" | "区别在可控与可核。我们用工具把模型的能力边界限定在'能查到的数据'里：工具结果压缩给模型，完整数据给前端；制度回答必须带引用；SQL 必须过安全闸门。" |
| 被问"数据脏怎么办？" | "看板上 AI 主动指出覆盖率 40%、3 条超过 100 分的异常成绩、学籍状态取值不统一（在读/在校）。我们选择暴露问题而不是粉饰。" |

## 附录 B：演示前自检清单

```powershell
# 1. 数据库可用
psql -h 127.0.0.1 -U postgres -d student_manage -c "select count(*) from student;"

# 2. 后端启动（含前端构建产物）
.\mvnw.cmd spring-boot:run

# 3. 三个关键接口自检
curl.exe http://localhost:8080/ai/status
curl.exe -X POST http://localhost:8080/ai/students -H "Content-Type: application/json" -d "{\"limit\":3}"
curl.exe -X POST http://localhost:8080/ai/insight

# 4. 浏览器打开
start http://localhost:8080/app/
```

- 确认 `#/dashboard` 的图表有数据（若前端有改动，先 `cd frontend; npm run build`）；
- 确认「AI 助手」空态引导卡片正常显示；
- 若使用大模型，先确认 `/ai/status` 的 `mode` 为 `remote`。
